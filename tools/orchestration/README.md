# Sherlock Playbook Orchestration Pipeline

Self-contained tooling that **generates** and **reviews** the Sherlock analysis-playbook
corpus (`techniques/**/*.yaml`) in parallel from the Watson analytic-plan corpus
(`../watson/techniques/**/*.json`), with atomic locking and per-playbook git commits.

There are **two agentic pipelines** plus **three deterministic helper tools**:

| Pipeline | What it does | Driver | Agent model |
|----------|--------------|--------|-------------|
| **Generate** | Create/update one playbook YAML per Watson plan | `pool.sh` → `run_one.sh` | default (Sonnet-class) |
| **Review/QA** | Audit & fix each playbook against its source plan | `pool_review.sh` → `review_one.sh` | `claude-opus-4-8`, `--effort max` |

> ### Authorized DEFENSIVE (blue-team) work
> Every agent only transcribes/QAs **log-based detection guidance** for activity
> catalogued by MITRE ATT&CK/D3FEND. It never writes malware or offensive tooling.
> Both prompt templates lead with a defensive-context preamble. If the headless
> usage-policy classifier refuses a technique (a `POLICYBLOCK` marker), that is a
> **false positive** — see [§7](#7-handling-policyblock-false-positives).

All paths below are relative to the repo root `/home/jovyan/analytic-dev/221b/sherlock`.
Watson is **strictly read-only**; every write lands in Sherlock.

## 1. Files

### Generation pipeline
| File | Role |
|------|------|
| `agent_prompt_template.md` | Headless prompt: derive ONE playbook YAML from ONE Watson plan. Placeholders `@@WATSON_JSON@@`, `@@SHERLOCK_YAML@@`, `@@STEM@@`, `@@MODE@@` (create/update), `@@DONE@@`. |
| `run_one.sh` | Process ONE plan: skip if done/blocked → atomic `mkdir` claim → render prompt → `claude -p` (30-min timeout) → on usage-policy refusal write `POLICYBLOCK`. |
| `pool.sh` | `pool.sh <MAXJOBS> [queue]` — launch a pool of `run_one.sh` workers; skips `DONE`/`POLICYBLOCK`. |
| `harvest.sh` | **Serial committer.** Validate each new `DONE` playbook (YAML parses, required keys, UUIDv4, ≥1 question) and `git commit` it individually; mark `COMMITTED`. |
| `watch.sh` | Every 5 min: run `harvest.sh`, append progress to `logs/_status.log`; exit when pool gone and agents idle. |
| `finalize.sh` | After the pool drains: clear stale `CLAIM`s, run 4 retry passes (`pool.sh`), final harvest. |

### Defensive retry (shared)
| File | Role |
|------|------|
| `agent_prompt_defensive_header.md` | Defensive-SOC preamble prepended for `POLICYBLOCK` retries. |
| `agent_prompt_template_defensive.md` | `agent_prompt_defensive_header.md` + `agent_prompt_template.md` (regenerated by concatenation). |
| `run_one_defensive.sh` | Re-run ONE blocked plan with the defensive template; clears its `POLICYBLOCK` on success. |

### Review / QA pipeline
| File | Role |
|------|------|
| `review_prompt_template.md` | Headless prompt (defensive preamble built in): audit ONE playbook against its source plan on five criteria and FIX in place. Placeholders `@@WATSON_JSON@@`, `@@SHERLOCK_YAML@@`, `@@STEM@@`, `@@DONE@@`. |
| `review_one.sh` | Review+fix ONE playbook with `--model claude-opus-4-8 --effort max` (60-min timeout). |
| `pool_review.sh` | `pool_review.sh <MAXJOBS> [queue]` — pool of `review_one.sh`; skips `REVIEWED`/`POLICYBLOCK`. |
| `harvest_review.sh` | **Serial committer.** Validate each `REVIEWED` playbook and **commit only if it actually changed** (`git diff --cached --quiet`); mark `RCOMMITTED`. |
| `watch_review.sh` | Periodic `harvest_review.sh` + progress to `logs_review/_status.log`. |
| `finalize_review.sh` | Retry passes for review stragglers; final harvest. |

### Deterministic helper tools (non-agentic; see [§5](#5-deterministic-helper-tools))
| File | Role |
|------|------|
| `convert_plan_to_playbook.py` | Fallback converter (Watson plan JSON → Sherlock playbook YAML) for techniques the agents cannot process. |
| `clean_urls.py` | Remove illustrative placeholder + truncated citation URLs from playbooks. |
| `audit_playbooks.py` | Verify coverage / structure / action-coverage / citation preservation / URL hygiene. |

### Data & state
| Path | Role |
|------|------|
| `queue.txt` | Work queue: one Watson-relative `techniques/.../<STEM>.json` path per line. |
| `_fragments/` | Generation markers: `<STEM>.CLAIM/`, `.DONE`, `.COMMITTED`, `.POLICYBLOCK` (gitignored). |
| `_review/` | Review markers: `<STEM>.CLAIM/`, `.REVIEWED`, `.RCOMMITTED`, `.POLICYBLOCK` (gitignored). |
| `logs/`, `logs_review/` | Per-stem agent logs + `_status.log`, `_finalize.log`, `_pool*.log` (gitignored). |

## 2. Marker-file lifecycle

Per technique stem, markers live in `_fragments/` (generate) or `_review/` (review):

```
queued ──run_one──▶ <STEM>.CLAIM/ (atomic mkdir)
                       │
   agent succeeds      │  agent fails (no marker)     usage-policy refusal
        ▼              ▼                               ▼
  <STEM>.DONE     CLAIM removed (re-queued)      <STEM>.POLICYBLOCK
        │ (review: .REVIEWED)
   harvest
        ▼
  <STEM>.COMMITTED   (review: .RCOMMITTED)
```

| Marker | Meaning | Effect |
|--------|---------|--------|
| `<STEM>.CLAIM/` | A worker owns it now | other workers skip |
| `<STEM>.DONE` / `.REVIEWED` | Agent finished | pool skips it |
| `<STEM>.COMMITTED` / `.RCOMMITTED` | Harvested + committed | harvest skips it |
| `<STEM>.POLICYBLOCK` | Usage-policy false positive | pool skips; resolve per [§7](#7-handling-policyblock-false-positives) |

> **Note:** `run_one.sh`/`review_one.sh` leave the `CLAIM/` dir in place on success
> (the `DONE`/`REVIEWED` marker is what subsequent runs check), so accumulated
> `CLAIM/` dirs for completed work are harmless.

## 3. The generation pipeline

Each agent reads ONE Watson plan and writes ONE playbook YAML + a `DONE` marker,
following `../tools/prompts/agent-create-playbooks.md`. Field mapping: `name` =
`"<technique_id>: <technique_name>"`; `id` = UUIDv4; `description` from evidence;
`type` = `technique`; `related` = one entry per parent tactic; `contributors` from
the plan; **one `questions` entry per distinct source action** (de-duplicated across
tactics) with `question`/`context`/`answer_sources` (data_sources + `NAI:`)/`range`/`queries`.

Date/version rules (this corpus): new playbooks `created`/`modified` = `2026-05-31`,
`version` `1.0`; updated playbooks preserve `id`+`created`, set `modified`=`2026-05-31`,
bump `version` `+0.1`. `run_one.sh` auto-selects `create`/`update` by whether the
target YAML exists.

```bash
cd /home/jovyan/analytic-dev/221b/sherlock
# (re)build the queue — all active Watson plans (archive + checkpoints excluded):
( cd ../watson && find techniques -name '*.json' \
    -not -path '*archive*' -not -path '*ipynb*' | grep -v checkpoint | sort ) \
  > tools/orchestration/queue.txt

nohup bash tools/orchestration/pool.sh 64     > tools/orchestration/logs/_pool.log     2>&1 &
nohup bash tools/orchestration/watch.sh       > tools/orchestration/logs/_watch.log    2>&1 &
nohup bash tools/orchestration/finalize.sh    > tools/orchestration/logs/_finalize_out.log 2>&1 &
tail -f tools/orchestration/logs/_status.log
```

Run a single technique:
```bash
bash tools/orchestration/run_one.sh techniques/attack/enterprise/T1059.001.json
bash tools/orchestration/harvest.sh
```

## 4. The review / QA pipeline

Each agent compares ONE playbook against its source plan and fixes it in place,
then writes a `REVIEWED` marker. The five criteria (full text in
`review_prompt_template.md`):

1. **Action coverage** — every distinct source action addressed by ≥1 question.
2. **Citation preservation** — every source-action `[title](url)`/bare URL preserved
   in the question `context` (citations belong in context, never in query pseudocode).
3. **Junior-analyst guidance** — context thoroughly explains what/why/how + thresholds
   + positive/negative interpretation, tactic-specifically.
4. **Faithfulness** — nothing introduced beyond the source; `answer_sources` derive
   only from that evidence item's `data_sources` + `nai`.
5. **Structure** — valid YAML, all keys; `id`/`name`/`type`/`created` preserved;
   `related` complete. If changed: `modified`=`2026-05-31`, `version` `+0.1`; if no
   change is warranted, the file is left byte-for-byte unchanged.

```bash
cd /home/jovyan/analytic-dev/221b/sherlock
nohup bash tools/orchestration/pool_review.sh 64  > tools/orchestration/logs_review/_pool.log 2>&1 &
nohup bash tools/orchestration/watch_review.sh    > tools/orchestration/logs_review/_watch.log 2>&1 &
nohup bash tools/orchestration/finalize_review.sh > tools/orchestration/logs_review/_finalize_out.log 2>&1 &
tail -f tools/orchestration/logs_review/_status.log
```

Run a single review:
```bash
bash tools/orchestration/review_one.sh techniques/attack/enterprise/T1059.001.json
bash tools/orchestration/harvest_review.sh
```

The agent model/effort is set in `review_one.sh`:
`claude -p "$prompt" --model claude-opus-4-8 --effort max ...`.

## 5. Deterministic helper tools

Non-agentic Python utilities for fallback generation, cleanup, and verification.
All resolve `SHERLOCK_ROOT`/`WATSON_ROOT` from their own location.

### `convert_plan_to_playbook.py` — policy-block / straggler fallback
When a technique is **persistently** `POLICYBLOCK`ed (and the defensive retry also
fails), transcribe it deterministically. Guarantees one question per distinct
action, all citations preserved in `context`, URL-free queries, faithful content.
Auto-detects create vs update (preserves `id`+`created`, bumps `version` on update).
```bash
python3 tools/orchestration/convert_plan_to_playbook.py --stem T1543.005
python3 tools/orchestration/convert_plan_to_playbook.py techniques/azure/AZT502.json
# then create the marker so the pool skips it, and harvest:
touch tools/orchestration/_review/T1543.005.REVIEWED   # or _fragments/<STEM>.DONE for generation
bash tools/orchestration/harvest_review.sh
```
> Prose is mechanical-but-faithful; prefer the agentic pipelines for best prose.

### `clean_urls.py` — placeholder + truncation cleanup
Removes illustrative placeholder URLs (containing `...`, `…`, `<`, `>`) unconditionally,
and removes/repairs truncated citation fragments. Exact source URLs are never touched;
queries are stripped of URLs; truncations in context are repaired to the unique full
source URL when determinable, else unwrapped to title.
```bash
python3 tools/orchestration/clean_urls.py            # dry-run (count)
python3 tools/orchestration/clean_urls.py --apply    # apply across corpus
python3 tools/orchestration/clean_urls.py T1039      # dry-run one stem
```

### `audit_playbooks.py` — full verification (use after every run)
```bash
python3 tools/orchestration/audit_playbooks.py            # all checks (exit≠0 on failure)
python3 tools/orchestration/audit_playbooks.py --urls     # only URL hygiene
python3 tools/orchestration/audit_playbooks.py --verbose  # list offending files
```
Checks: [1] coverage (no missing/orphan), structure (parse/keys/UUIDv4/≥1 question),
[2] action-coverage parity, [4] citation preservation (action-URL based), [5] URL
hygiene (no placeholders/truncations). Citation/URL checks are **parse-based**
(load the YAML) — raw-text grep over the file mis-splits double-quoted scalars that
contain `\n` escapes and will report false positives.

## 6. The work queue

`queue.txt` lists every in-scope Watson plan (Watson-relative path), shared by both
pipelines. Scope: all of `techniques/{attack/{enterprise,mobile,ics},aws,azure,d3fend}`;
**excluded:** `techniques/archive/` (deprecated) and `.ipynb_checkpoints`. Output path

`techniques/attack/enterprise/T1133.json` → `techniques/attack/enterprise/T1133.yaml`.
Rebuild command is in [§3](#3-the-generation-pipeline). Current size: 1205 plans.

## 7. Handling POLICYBLOCK false positives

1. **Automatic defensive retry** (generation): `finalize.sh` does not auto-retry
   blocks; run it manually:
   ```bash
   for pb in tools/orchestration/_fragments/*.POLICYBLOCK; do
     s="$(basename "$pb" .POLICYBLOCK)"
     p="$(grep -m1 "/${s}\.json$" tools/orchestration/queue.txt)"
     [ -n "$p" ] && bash tools/orchestration/run_one_defensive.sh "$p"
   done
   bash tools/orchestration/harvest.sh
   ```
   For **review** blocks, clear the marker and re-run (the review template already
   carries the defensive preamble):
   ```bash
   rm -f tools/orchestration/_review/<STEM>.POLICYBLOCK
   rm -rf tools/orchestration/_review/<STEM>.CLAIM
   bash tools/orchestration/review_one.sh "$(grep -m1 "/<STEM>\.json$" tools/orchestration/queue.txt)"
   ```
2. **Deterministic fallback** — if a technique still won't run headless, use
   `convert_plan_to_playbook.py` (see [§5](#5-deterministic-helper-tools)), then create
   the marker and harvest. In the production runs, `AZT502`/`AZT508` (generation) and
   `T1543.005` (review) were completed this way.

## 8. Concurrency tuning

Atomic claiming makes any worker count safe. Budget ~0.5 GB RAM per agent.
Generation agents are light (~2 min each, default model); review agents are heavier
(`opus-4-8` + `--effort max`, ~1.5–several min each). Both production runs used **64**
concurrent agents. To scale up mid-run, launch another `pool.sh`/`pool_review.sh`.

---

## 9. Safety & concurrency invariants

- **Disjoint writes** — each agent writes only its one YAML + its one marker.
  Agents never run git, never edit Watson, never touch shared files.
- **Atomic claiming** — `mkdir <STEM>.CLAIM` is atomic on POSIX; a losing racer exits.
- **Single serial committer** — only `harvest*.sh` commits (no git index races).
  `harvest_review.sh` commits **only when the file actually changed**.
- **Idempotent + resumable** — markers make every stage safe to re-run.
- **Bounded agents** — `timeout` wraps each agent (1800 s generate, 3600 s review).
- **Checkpoint hygiene** — `.ipynb_checkpoints` excluded from queue and harvest.

## 11. Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| Agent log ends "marker created" but no marker in `_fragments`/`_review` | agent wrote the marker to a path relative to the wrong CWD (lands in stray `techniques/*/tools/...`) | the YAML is usually correct; verify with `audit_playbooks.py`, then `touch` the canonical marker and `rm -rf techniques/*/tools` |
| `[POLICYBLOCK] <STEM>` | usage-policy false positive | [§7](#7-handling-policyblock-false-positives) |
| `[FAIL] <STEM> (no marker)` | agent crashed/timed out | inspect `logs*/<STEM>.log`; markers make re-runs safe |
| `harvest*.sh` says `INVALID yaml` | agent wrote malformed YAML | re-run the technique |
| Nothing committing | watcher not running | start `watch*.sh` or run `harvest*.sh` manually |
| Audit reports citation "partial" but `--urls` is clean | raw-text vs parse: double-quoted scalars with `\n` escapes mis-split under raw grep | trust the parse-based `audit_playbooks.py` numbers |
| Stale `CLAIM/` blocks a re-run | crashed worker | `finalize*.sh` clears stale claims, or `rm -rf _*/<STEM>.CLAIM` |

  71 playbooks via `clean_urls.py`; final audit — 0 placeholders, 0 truncations,
  17,030 source citations intact.
